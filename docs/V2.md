# ReferralRail v2

ReferralRail v2 is deployed separately from the frozen v1 system on Studio
development chain 61997.

The v2 flow is campaign creation and full escrow funding, temporary referral
reservation, candidate acceptance with a contract-derived GitHub challenge,
fresh pull request submission, independent GenLayer judgment, bounded
inconclusive retry or timeout recovery, permissionless settlement, and final
refund of unused campaign capacity.

Campaign escrow is conserved as:

`initial_funding = paid + refunded + still_locked`

A failed or expired position releases its occupied capacity while intake is
open. It does not immediately transfer the backing to the employer. After
intake closes and all potentially payable positions are resolved, the
permissionless `finalise_campaign` action returns unused capacity backing to
the immutable employer address.

The v2 contract addresses and binding receipt are in
`deployment/v2-61997.json`. Configure the v2 frontend with
`NEXT_PUBLIC_REFERRALRAIL_V2_ADDRESS` and
`NEXT_PUBLIC_OUTCOME_JUDGE_V2_ADDRESS`. These are separate from the v1
variables and must not replace the v1 production values.

Candidate ownership proof is an exact challenge generated after acceptance.
The candidate must publish it in a PR comment authored by the bound GitHub
login. The judge treats GitHub content as untrusted evidence and independently
checks repository, branch, author, freshness, challenge ownership and bounded
patch content before substantive evaluation.
